# Executing Plans

1. Read the plan, relevant working documents, and affected current files.
2. Identify outdated assumptions, missing decisions, or a material stack conflict before editing; ask rather than guess.
3. Complete one planned slice at a time while preserving the approved module and ownership boundaries.
4. Run focused verification appropriate to each slice.
5. Report completed plan items, evidence actually obtained, and remaining work.

Do not automatically create branches, commits, worktrees, dependencies, networking, or persistence. Follow the user's authorization and repository guidance for state-changing actions. Return to the user for approval if the plan changes product direction, asset rights, data durability, package choice, or architecture scope.
